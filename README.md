# نظام إدارة المؤسسة (نسخة خفيفة لـ ~20 موظفاً)

موظفون • حضور • رواتب • مخزون • محاسبة مبسطة • طلبات إدارية • **توقيعات إلكترونية وملف PDF مختوم**.
Python + Flask + SQLite. الواجهة بنمط ERPNext (شريط علوي + قائمة جانبية + مؤشرات حالة + نماذج وقوائم)
مكتوبة من الصفر بتنسيق خاص (لم يُنسخ أي كود من ERPNext).

## التشغيل على Vercel (عبر الإنترنت)
النظام يكتشف تلقائياً وجود `DATABASE_URL` فيستخدم **Postgres (Neon)** بدل SQLite، ويحفظ المرفقات والملفات
المختومة داخل قاعدة البيانات (جدول `files`)، لأن نظام ملفات Vercel للقراءة فقط.
- **الارتباطات المطلوبة:** تكامل **Neon** فقط (يضيف `DATABASE_URL` تلقائياً).
- **متغيرات مستحسنة (Settings ← Environment Variables):**
  `ORG_NAME` اسم المؤسسة، `BASE_URL` رابط الموقع (مثل `https://orgsys.vercel.app`) ليظهر صحيحاً في رمز QR،
  و`SECRET_KEY` اختياري (إن لم يُحدَّد يُولَّد تلقائياً ويُحفظ في قاعدة البيانات).
- **نقل بيانات SQLite موجودة إلى Neon:**
  `DATABASE_URL=postgresql://... python migrate_to_postgres.py data/org.db`
- **صورة الختم** على Vercel: تُنقل `data/stamp.png` بسكربت النقل أعلاه (تُحفظ في جدول `files` باسم `stamp.png`).
- النسخة الاحتياطية على Postgres تُنزَّل بصيغة JSON، ويمكن أيضاً استعادة نقاط زمنية من لوحة Neon.
- حد المرفق على Vercel هو 4MB.

## التشغيل المحلي
```bash
python -m venv venv && source venv/bin/activate      # ويندوز: venv\Scripts\activate
pip install -r requirements.txt
python app.py                                        # http://127.0.0.1:8000
```
عند أول تشغيل يُنشأ المستخدم `admin` وتُطبع كلمة مروره في الطرفية (أو حدّدها بـ `ADMIN_PASSWORD`). غيّرها فوراً.
متغيرات اختيارية: `ORG_NAME` اسم المؤسسة (يظهر في الختم)، `ORG_DATA_DIR`، `HOST`/`PORT`، `HTTPS=1`،
`BASE_URL` (رابط النظام الذي يُكتب في رمز QR، مثل `http://192.168.1.10:8000`).
**الترقية من الإصدار السابق:** شغّل النسخة الجديدة على نفس مجلد `data` وستُرقّى قاعدة البيانات تلقائياً.

## دورة الطلب المالي (الأساسية)
1. **الموظف** يقدّم «طلب مالي» (تصنيف + مبلغ + تفاصيل + مرفق) ← إشعار للمدير.
2. **المدير** يراجع ويوقّع بالموافقة ← إشعار للمالية.
3. **المالية** تُنفّذ الصرف: المبلغ الفعلي + الحساب + التاريخ + رقم الإيصال، وتوقّع. يُسجَّل مصروف تلقائياً في المحاسبة، ويُشعَر الموظف والإدارة بإتمام الصرف.
4. **الإدارة** تراجع بيانات الصرف وتوقّع الاعتماد النهائي.
5. يُولَّد تلقائياً **ملف PDF مختوم** فيه: بيانات الطلب والصرف، توقيع كل جهة (صورة + اسم + وقت)، ختم دائري، رمز QR ورمز ختم وبصمة SHA-256.

## التوقيع الإلكتروني
- كل مستخدم يرسم توقيعه مرة واحدة من «توقيعي الإلكتروني».
- كل اعتماد يتطلب **إعادة إدخال كلمة المرور**، ويُحفظ مع التوقيع: الاسم، الوقت، عنوان IP.
- التوقيعات مربوطة ببصمات تشفيرية متسلسلة (بيانات الطلب + كل توقيع سابق)؛ أي تعديل لاحق في المبلغ أو الملاحظات أو التوقيع يُكشف ويظهر تحذير أحمر.
- المسؤول يستطيع التوقيع **بالإنابة** عن أي جهة غائبة، ويُسجَّل ذلك ويظهر في الملف المختوم.
- التحقق العام بلا دخول: `/verify` (رمز الختم + فحص ملف PDF بمقارنة بصمته).
- لاستخدام ختم مؤسستك الحقيقي ضع صورة PNG باسم `stamp.png` داخل مجلد `data` وسيُستعمل بدل الختم المرسوم.

## الأدوار
| الدور | يستطيع |
|---|---|
| admin الإدارة العليا | كل شيء + المستخدمون + السجل + النسخ الاحتياطي + التوقيع بالإنابة |
| manager مدير | يوافق على الطلبات، يرى الموظفين (بلا رواتب) والحضور والمخزون |
| hr موارد بشرية | الموظفون، الحضور، توليد وتعديل الرواتب |
| accountant محاسب | المحاسبة، تنفيذ صرف الطلبات المالية، صرف الرواتب |
| store أمين مخزن | الأصناف وحركات المخزون واعتماد صرف المواد |
| employee موظف | تقديم الطلبات ومتابعتها |

أنشئ مستخدماً لكل شخص من «المستخدمون» واربطه بملف الموظف (ضروري للإجازات).

## مسارات الطلبات (قابلة للتعديل في `TYPES` أعلى app.py)
- مالي: مدير ← مالية (صرف) ← إدارة (اعتماد)
- إجازة: مدير ← موارد بشرية (يخصم الرصيد ويسجّل «إجازة» في الحضور)
- صرف مواد: مدير ← أمين المخزن (يخصم من المخزون)
- إذن خروج: مدير • طلب عام: مدير ← إدارة

لا أحد يوافق على طلبه. تُتخطى خطوة الموافقة التي تطابق دور مقدّم الطلب، أما خطوة الصرف فلا تُتخطى أبداً
(محاسب يطلب مبلغاً لنفسه ⇒ يوقّع الصرف المسؤول بالإنابة، فلا يصرف لنفسه).

## للإنتاج
```bash
ORG_NAME="اسم مؤسستك" BASE_URL="http://عنوان-الخادم:8000" waitress-serve --host=0.0.0.0 --port=8000 app:app
```
ضعه خلف Nginx/Caddy مع HTTPS إذا فُتح من خارج الشبكة المحلية، وفعّل `HTTPS=1`.
النسخ الاحتياطي: زر «نسخة احتياطية» (admin) + انسخ مجلد `data` (فيه المرفقات والملفات المختومة).

## حدود يجب معرفتها
- التوقيع هنا توقيع إلكتروني داخلي موثّق (كلمة مرور + بصمات + سجل)، وليس «توقيعاً موصوفاً» من جهة تصديق. قيمته القانونية تختلف حسب بلدك، فراجع مستشارك القانوني إن لزم.
- المحاسبة مبسطة (ليست قيداً مزدوجاً) ولا تغني عن محاسب معتمد.
- الإشعارات داخل النظام فقط (بلا بريد/واتساب).
- المدير يوافق على طلبات كل الموظفين (بلا ربط بالأقسام).
- الخط المرفق في `fonts/` هو DejaVu Sans (ترخيص حر).

## الاختبار
`python test_app.py` — نحو 100 اختبار (الصلاحيات، دورة الصرف، التوقيع، الختم، كشف التلاعب، المخزون، الرواتب).
لتشغيلها على Postgres في مخطط منفصل: `PG_SCHEMA=orgsys_test DATABASE_URL=<رابط غير مجمّع> python test_app.py`
(أنشئ المخطط أولاً واحذفه بعد الانتهاء).
